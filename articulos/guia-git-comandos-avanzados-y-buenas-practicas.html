Git Avanzado: Rebase Interactivo, Bisect, Reflog y Conventional Commits

Por Alejandro S. Fuentes (Ingeniero de Software) • 3 de abril de 2026 • Lectura: 10 min
Figura: Compactación y limpieza de ramas de trabajo antes de fusionar a la rama principal (main).

La mayoría de programadores dominan el flujo básico: git add, git commit y git push. Sin embargo, en proyectos colaborativos de gran envergadura o en empresas con estándares estrictos de integración continua (CI/CD), la capacidad de mantener un árbol de Git legible, atómico y libre de ruido es lo que distingue a un desarrollador senior.

Publicidad

1. Rebase Interactivo: git rebase -i

Permite reescribir los últimos commits antes de abrir una Pull Request. Puedes fusionar commits provisionales («fix typo», «wip») mediante squash o fixup:

# Revisa y reorganiza los últimos 3 commits
git rebase -i HEAD~3

# En el editor que se abrirá:
# pick a1b2c3d feat: agregar autenticacion oauth2
# squash e4f5g6h fix: corregir typo en token
# squash i7j8k9l test: agregar pruebas unitarias

2. Encontrar Bugs Históricos con git bisect

¿Tu aplicación falla en producción pero no sabes qué commit de los últimos 200 introdujo el error? git bisect ejecuta una búsqueda binaria algorítmica:

git bisect start
git bisect bad                 # El commit actual tiene el bug
git bisect good v1.4.0         # La versión v1.4.0 funcionaba correctamente
# Git irá alternando commits y preguntándote hasta señalar al culpable exacto.

3. git reflog: Tu Red de Seguridad ante Desastres

Si alguna vez ejecutaste por error git reset --hard o borraste una rama que aún no habías subido, no entres en pánico. Git guarda un registro local de cada movimiento del puntero HEAD en el reflog durante 30 a 90 días:

git reflog
# Localiza el hash anterior al error (ej. HEAD@{2})
git reset --hard HEAD@{2}
Nunca hagas rebase en ramas públicas compartidas (como main o develop) donde otros compañeros ya hayan descargado commits, ya que alterarás los hashes históricos forzando conflictos masivos.
Un estándar de nomenclatura de mensajes (ej. feat:, fix:, docs:, refactor:) que permite generar changelogs automáticos y determinar versiones semánticas (SemVer) sin intervención manual.
