Docker para Principiantes: Cómo Desplegar Aplicaciones en Contenedores sin Morir en el Intento

Por Alejandro S. Fuentes (DevOps & Web) • 4 de abril de 2026 • Lectura: 9 min
Figura: Arquitectura de virtualización pesada (Hipervisor) vs Contenerización ligera a nivel de proceso.

La infame frase «en mi máquina sí funciona» ha sido históricamente la pesadilla de cualquier equipo de desarrollo. Diferencias sutiles de versiones de librerías, dependencias del sistema operativo o variables de entorno provocaban fallos al pasar código a producción. Docker soluciona este problema empaquetando el código junto a todas sus dependencias exactas en un contenedor estandarizado.

Publicidad

1. Escribiendo tu Primer Dockerfile

Un Dockerfile es la receta paso a paso para construir la imagen de tu aplicación:

# Usar imagen ligera de Node.js
FROM node:20-alpine

# Definir directorio de trabajo
WORKDIR /app

# Copiar manifiestos e instalar dependencias
COPY package*.json ./
RUN npm ci --only=production

# Copiar código fuente y exponer puerto
COPY . .
EXPOSE 3000

# Comando de ejecución
CMD ["node", "server.js"]

2. Orquestación con docker-compose.yml

Para levantar una aplicación web junto con su base de datos (por ejemplo, Postgres o Redis) sin configurar nada a mano:

version: '3.8'
services:
  web:
    build: .
    ports:
      - "3000:3000"
    environment:
      - DB_HOST=db
  db:
    image: postgres:16-alpine
    environment:
      POSTGRES_PASSWORD: secret_password
    volumes:
      - pgdata:/var/lib/postgresql/data

volumes:
  pgdata:

3. Los 4 Comandos que Usarás el 90% del Tiempo

  • docker build -t mi-app .: Construye la imagen local.
  • docker run -p 3000:3000 mi-app: Ejecuta el contenedor asociando puertos.
  • docker-compose up -d: Levanta todos los servicios en segundo plano.
  • docker ps: Muestra los contenedores en ejecución y su consumo.
